Chapter 4

Arrays and strings

A fixed collection, declared once

dim gives a scalar a name; it gives an array a name and a shape. Classic BASIC has no REDIM — once dimensioned, an array’s size is fixed for the rest of the program, so its bound is a design decision, not a runtime one.

dim scores%(30)
dim i%, total%

for i% = 0 to 30
    scores%(i%) = i% * 2
    total% = total% + scores%(i%)
end for

print "elements: "; sizeof(scores%)
print "total: "; total%

dim scores%(30) declares indices 0 through 30 inclusive — 31 elements, BASIC’s default OPTION BASE 0. sizeof(scores%) reads that bound back, so a loop never has to repeat a literal that could drift out of sync with the declaration. A second axis works the same way — dim grid%(2, 2) — except sizeof then needs a zero-based axis number: sizeof(grid%, 0), sizeof(grid%, 1).

Passing an array without losing track of its size

A function parameter can accept an array of unknown size by writing ? for each axis instead of a number. The transpiler works out how much storage the parameter needs by scanning every call site, and carries the real bound along automatically — sizeof inside the function body reads it back exactly as it would outside one.

function sumArr%(byref arr%(?))
    dim i%, total%
    for i% = 0 to sizeof(arr%)
        total% = total% + arr%(i%)
    end for
    return total%
end function

dim values%(4)
values%(0) = 10
values%(1) = 20
print sumArr%(values%)

An array argument is passed with its bare name — never (), never a separately hand-typed count that could silently disagree with the array’s own dim. As with a scalar parameter, byval (the default) copies the array in only; byref copies it in and back out again once the call returns, since BASIC has no real aliasing to give the function a direct reference to the caller’s storage. An array argument that sumArr% only reads should stay byval — a byref array nothing writes to just pays for a copy-out loop it doesn’t need.

Once an array is no longer needed, erase releases its storage; referencing it afterward is a runtime error until it’s dimed again.

Strings are text, not character arrays

A BASCAL string is a single value with the $ suffix, not an array you index by character. + concatenates; a family of built-in functions reads and rebuilds substrings.

dim name$
name$ = "Ada Lovelace"
print left$(name$, 3) + " " + mid$(name$, 5, 8)
print instr(name$, "Love")
mid$(name$, 1, 3) = "Amy"
print name$

left$(s$, n) and right$(s$, n) take the first/last n characters; mid$(s$, start, len) takes len characters from a 1-based start (the length is optional — omit it to take the rest of the string). instr(s$, needle$) returns the 1-based position of the first match, or 0. len(s$), str$(n), val(s$), chr$(code%), and asc(s$) convert between numbers, characters, and text the same way they do in classic BASIC.

mid$(...) also has a statement form, used on the left of an assignment rather than inside an expression: mid$(name$, 1, 3) = "Amy" overwrites three characters starting at position 1 in place, rather than building a new string. It’s the one place the same name means two different things depending on which side of = it appears on.

A handful of further string operations — ltrim$, rtrim$, ucase$, lcase$ — aren’t real MBASIC/BASCOM builtins, so BASCAL ships them as an ordinary library instead of pretending otherwise. See The standard library for the complete list and why they need require.
