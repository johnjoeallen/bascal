Chapter 7

Errors, labels, and embedded data

Naming a destination without a line number

Structured if and loops cover ordinary control flow, but a few classic BASIC mechanisms — error trapping among them — are built on jumping to a specific place in the program. BASCAL keeps that capability without asking the source to carry numbered lines: a label: names a destination, and the compiler assigns the real line number for it.

gosub greet
goto after

greet:
    print "Hello!"
    return

after:
    print "done"

goto label jumps unconditionally; gosub label jumps and remembers where to come back to, resumed by a matching return — this is BASIC’s own subroutine mechanism, distinct from a BASCAL function/procedure call, and is normally only reached for for the handful of forms in this chapter that require it.

Handling an error at the point that needs it

A runtime error transfers control to a handler installed with on error goto, the same way any other language’s exception handling redirects execution — except the handler is just another label, and returning from it is explicit.

on error goto handler
result% = 10 / zero%
print "unreachable"
goto continue

handler:
    print "error "; err; " on line "; erl
    resume continue

continue:
    print "recovered"

Inside the handler, the no-suffix pseudo-variables err and erl hold the failing error code and line. resume retries the statement that failed; resume next skips it and continues with the one after; resume label — shown above — jumps somewhere else entirely, the usual shape when the failing statement can’t simply be retried. on error goto 0 disables the trap, letting an error terminate the program again. A program can also raise or re-raise one deliberately with error code%.

Shipping small constant tables with data

Classic BASIC’s data/read pair embeds a small constant table directly in the program instead of a separate file, useful for exactly the kind of fixed lookup table a record file would be overkill for.

dim country$(2), capital$(2)
dim i%

for i% = 0 to 2
    read country$(i%), capital$(i%)
end for

print country$(0); " "; capital$(0)

data "USA", "Washington"
data "France", "Paris"
data "Japan", "Tokyo"

data statements can appear anywhere in the source — the compiler gathers them into one sequential table regardless of where they’re written. Each read pulls the next value off that table, left to right, matching each variable’s declared type. restore rewinds back to the first data statement so the table can be read again from the start; restore label rewinds to whichever data statement immediately follows that label instead, useful when a program embeds more than one table and needs to choose between them.
