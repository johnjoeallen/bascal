Chapter 1

A first program

Start with the whole

BASCAL files use the .bcl extension. The bcc compiler turns one into classic BASIC or C. Start by describing the work in the order a reader expects to see it.

program hello

dim name$

print "What is your name";
input name$

if name$ = "" then
    print "Hello, stranger."
else
    print "Hello, " + name$ + "."
end if
end

Save this as hello.bcl and run bcc hello.bcl. The default backend creates hello.bas; bcc --target c hello.bcl emits C instead. This example compiles with both backends. The C backend is almost complete, and the manual’s Backends section lists its remaining limits.

Every file declares what it is

program hello is required: every .bcl file begins by saying what it is. It is either a runnable program <name>, a library <name> loaded with require, or a shared <name> file containing only variable declarations. bcc rejects a root file without this header instead of guessing. A final bare end closes the program. The compiler could infer it from the end of the file, but writing it keeps each program’s shape consistent.

Most later examples are fragments: the useful lines without a program name header or final end. Add both when you turn a fragment into a file to compile.

Read it from top to bottom

dim name$ declares a string variable. print and input are familiar BASIC operations. The important difference is the decision: if has a visible beginning, alternatives, and an end if. There are no numbered exits to find.

BASCAL makes control flow easy to read in the source, then emits the needed constructs for the selected target.

The next chapters explain the declarations, expressions, and blocks used here. Later chapters give the detailed language and command-line rules.
