Chapter 8

The standard library

Builtins that pass straight through

Most of what a BASCAL program calls without declaring is simply real BASIC, unchanged: the string functions from the previous chapter (len, mid$, left$, right$, instr, str$, val, chr$, asc), the numeric family (sqr, abs, int, fix, sgn, sin, cos, tan, atn, log, exp), the explicit conversions (cint, clng, csng, cdbl), and randomness (rnd, randomize).

print sqr(2.0); " "; sin(0.0); " "; cint(3.7)

These need no require — they compile to a direct call in the generated BASIC (or a small, self-contained equivalent in C), exactly as if you had written the target dialect by hand.

Functions BASCAL ships because the target doesn’t have them

A handful of everyday operations — trimming whitespace, changing case — feel like they should be builtins too, but real MBASIC/BASCOM 2.00 doesn’t have them (verified directly against a real IBM BASIC Compiler 2.00 under DOSBox-X, not assumed). Rather than silently emit a call to a function that wouldn’t actually exist on the target, BASCAL ships its own implementations as an ordinary library — which means they need the same require any other library function would.

require com.bascal.stdlib.ucase
require com.bascal.stdlib.ltrim

dim s$
s$ = "  hello world"
print ucase$(ltrim$(s$))

The complete set: ltrim$(s$)/rtrim$(s$) strip leading/trailing spaces; ucase$(s$)/lcase$(s$) change letter case (only a-z/A-Z, no locale-awareness); error$(code%) turns a runtime error code — the kind err holds inside an on error goto handler — into a human-readable message. Each lives under com.bascal.stdlib and needs its own require line, same as any library from Functions, procedures, and libraries.

Not every less-common function needs this treatment. string$, fix, hex$, and oct$ really are genuine BASCOM 2.00 builtins, so they pass straight through like the rest of the first section — require is only for the handful BASCAL had to build itself.

When in doubt about whether a given function needs a require, the compiler settles it either way: calling a real builtin needs none and works immediately, while calling one of BASCAL’s own without the matching require fails to resolve, rather than silently compiling into a call the target doesn’t actually have.
